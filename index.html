self-release 说一句话就能发布或更新 skill · 坐标写在 skill 自己身上

解决什么问题

发布 skill 时每次都要手打仓库地址、翻版本号、想分支名——重复且容易错。更麻烦的是换一台机器后，本地 skill 不知道自己的仓库在哪，用户还得重新找链接。

这个 skill 把坐标钉在 skill 自己身上。发布一次，写进 .release.json，之后任何机器、任何会话，说一句「更新 X」就能拉最新版。

# 以前：得先问用户「这个 skill 的仓库是哪个？」
# 现在：
python3 scripts/release.py --update

一句话流程

定位→ 递增版本→ 本地验证→ 同步 clone→ 提交推送→ 打 tag→ 汇报

三种使用场景

场景 A · 发布（本机改完代码）

cd ~/.dsh/skills/<你的 skill>

python3 scripts/release.py --check                  # 定位仓库 / 版本 / tag
python3 scripts/release.py --bump patch --dry-run   # 预览版本变化
python3 scripts/release.py --bump patch             # 真写入（同步三处）
python3 scripts/release.py --verify                 # 本地 vs 远端 blob

场景 B · 更新（别的机器，本地已有）

cd ~/.dsh/skills/X
python3 scripts/release.py --update

自动区分两条路径：git 仓库走 fetch + reset --hard；非 git 目录走 tarball 覆盖。两者都保留本地 .release.json。

场景 C · 新装（新机器，连本 skill 都没有）

curl -fsSL https://raw.githubusercontent.com/wpc6666/self-release/main/install.sh | bash

一条命令装好并自动写入 .release.json。幂等——已装过会转为更新流程。

场景 D · 装其他 skill（本 skill 已就位）

python3 ~/.dsh/skills/self-release/scripts/release.py \
  --init https://github.com/<user>/<repo>.git
python3 ~/.dsh/skills/self-release/scripts/release.py \
  --install --target ~/.dsh/skills/X

坐标只需提供一次，之后永久免链接。

「一句话更新」靠什么成立

用户说「更新 X」，agent 不问任何东西，靠三级兜底：

级别前提agent 动作
0本机连 self-release 都没有跑上面那条 install.sh curl 引导命令
1X/.release.json 存在cd X && python3 scripts/release.py --update
2只有 manifest.json 的 repository同上（自动回退读 manifest）
3什么坐标都没有这时才问一次仓库地址 → --init 钉死 → 之后永久免问

「不需要原始链接」的准确含义：链接只需提供一次，写进 skill 自己的 .release.json，之后永远不用再提供。唯一需要记住 URL 的地方是第 0 级那条 curl 引导命令。

全部命令

命令作用
--check定位：仓库地址、当前版本、最近 tag、分支同步状态
--bump patch递增版本，同步 SKILL.md + manifest.json + CHANGELOG.md
--bump minor新增向后兼容功能时用
--bump major破坏性变更时用
--dry-run配合 --bump，只预览不写文件
--verify比对本地文件 blob 与远端 GitHub blob
--init <url>钉死仓库坐标，写入 .release.json
--install按坐标安装（新机器首次）
--update按坐标拉最新版（保留 .release.json）
--list列出所有已装 skill 的版本与发布坐标
install.sh引导安装器（curl ... | bash），幂等

自动定位规则

按优先级依次尝试，命中即停：

目标优先级
仓库地址.release.json 的 repo → .git/config 的 origin → 向上 6 层找 .git → manifest.json 的 repository → SKILL.md 正文首个 GitHub 链接
当前版本manifest.json 的 version → SKILL.md frontmatter → 一级标题里的 vX.Y.Z
分支名git branch --show-current（fork 仓库常为 master）

全部落空时 --check 返回 exit=2 并打印排查清单，此时应停下来问用户——不猜、不新建仓库。

接入新 skill

mkdir -p <skill_dir>/scripts
cp ~/.dsh/skills/self-release/scripts/release.py <skill_dir>/scripts/

cd <skill_dir>
python3 scripts/release.py --init https://github.com/<user>/<repo>.git --subdir "<路径>"

同时确认 manifest.json 至少有 id 和 version，最好补 repository 作为兜底。

边界与红线

情况处理
找不到仓库地址停下来问用户，不猜、不新建仓库
本地和 clone 不一致查原因（可能上次漏同步），不强行 --force
git push 报 TLSGitHub 偶发抖动，直接重试，不改 git 配置
推送后 raw CDN 还是旧内容正常现象，用 git ls-remote + gh api contents 验证
目标目录非空拒绝写入，先问用户
用户没说要发布只改本地，不提交、不推送、不打 tag

环境要求

  • Python 3.8+（只用标准库，无第三方依赖）
  • git
  • gh CLI（仅 --verify 需要）
